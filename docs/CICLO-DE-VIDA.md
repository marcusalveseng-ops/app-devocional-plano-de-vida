# Ciclo de vida do app

## 1. Planejar

Registrar o objetivo no roadmap. Criar uma issue para cada funcionalidade ou problema, descrevendo resultado esperado e critérios de aceite.

## 2. Decidir

Registrar escolhas relevantes em [Decisões](DECISOES.md), incluindo contexto, alternativas e consequências. Atualizar a documentação quando uma escolha mudar.

## 3. Desenvolver

Criar uma branch a partir da branch principal. Manter commits focados e associar a mudança à issue correspondente. Guardar no Git código, documentação e configurações de exemplo; manter credenciais, dados pessoais e conteúdo privado dos usuários fora do repositório.

## 4. Validar e revisar

Abrir um pull request com problema, resultado e evidências de validação. Executar os testes adequados à mudança e verificar os critérios de aceite antes de integrar. Quando houver automação de testes, documentar como executá-la no README.

## 5. Publicar

Atualizar o changelog, identificar a versão com uma tag e criar a release. Registrar ambiente, endereço publicado, validações e como restaurar a versão anterior. Confirmar o funcionamento no ambiente publicado antes de marcar a entrega como concluída.

## 6. Manter

Registrar falhas e feedback em issues. Priorizar correções e melhorias no roadmap. Manter instruções de uso, decisões e notas de versão consistentes com o comportamento entregue.
